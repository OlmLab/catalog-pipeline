How to contribute

A table keyed by run accession (SRR/ERR/DRR) or BioSample (SAMN/SAMEA/SAMD) joins directly. Tables keyed by the paper's own sample names (e.g. T1_S23) need an ID key as well — the archive holds no such names. Ages as numbers with a unit; controlled vocabularies are in Fields.

Licence and privacy

By contributing you confirm that the uploaded table may be redistributed under CC-BY-4.0, or you ask that only derived values be published (the file is then kept privately for audit). Upload research metadata only: no participant names, no e-mail addresses, no free-text clinical notes. Your GitHub login is the provenance record; it is stored hashed in the package.

What happens next

  1. Contribute opens a prefilled GitHub Issue (label contribution); drag-and-drop your CSV/TSV/XLSX (≤ 50 MB) into the note field. A GitHub account is needed.
  2. Deterministic ingest (daily): the pipeline downloads the attachment, records its sha256 and checks whether an identifier column joins to the study's own run accessions, sample keys, sample titles or library names. It comments on the Issue with a verdict — accepted_for_review, unjoinable (with the ID form it saw and what key is missing), duplicate_of_existing or rejected (type/size). Nothing you upload is executed.
  3. Curator review: accepted tables go through the same extraction contract as journal supplements (route R2, every value with evidence, conflicts to the conflict queue — never a silent overwrite).
  4. Next release: applied values carry release_added and the study page shows the attribution ("per-sample table contributed by <login>, <date>").

Claim a task to avoid duplicate effort: comment "working on it" on the study's Issue (open one with the Contribute button if none exists yet). Open contribution Issues: github.com › {{ cs.repo }} › issues · label:contribution.
